같은 키·값, 다른 저장 비용

구조 모형 · 일반 Node 사용 · 키를 새 Integer 객체로 박싱한 경우 · 실제 바이트 크기 아님

HashMap<Int, String>

버킷 배열 Node[] · 배열 헤더 1개
슬롯은 Node 참조를 저장 · 빈 슬롯도 공간 사용
↓ 슬롯이 가리키는 별도 객체

SparseArray<String>

키 배열 int[] · 배열 헤더 1개
인덱스키 값 직접 저장
같은 인덱스끼리 한 쌍 ↕
값 배열 Object[] · 배열 헤더 1개
인덱스값 객체 참조
항목마다 필요 없는 것
Integer 객체 + Node 객체
Node의 객체 헤더 + hash + key 참조 + next 참조
양쪽의 값 참조 ↓ 같은 String 객체들
공통 비용 제외: 컨테이너 객체 자체와 값 객체. 객체 헤더는 런타임 관리 공간이며 null 참조 필드도 자리를 차지함.
Integer 캐시를 재사용하면 새 키 객체 비용은 줄어듦. SparseArray에도 남는 배열 용량은 존재. 노드·박싱을 생략하는 것이 핵심.
